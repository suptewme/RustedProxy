# RustedProxy

**RustedProxy** — свободный Android-клиент для прокси и VPN-тоннеля: единый интерфейс для socks5/socks4, HTTP(S), Shadowsocks, Trojan и VLESS, встроенный проверщик узлов, обход блокировок и DPI, DNS с защитой от утечек и умная маршрутизация. Всё работает на устройстве: без аккаунтов, рекламы и телеметрии.

- Движок тоннеля, сканер и парсеры ссылок написаны на **Rust** (`rust_core/`), общаются с приложением через FFI/JNI.
- Интерфейс — **Flutter** с **Material 3**, адаптируется под жестовую, двух- и трёхкнопочную навигацию.
- Android-часть на **Kotlin**: `VpnService`, плитка в шторке быстрых настроек, root-функции, автозапуск.

> Проект был сделан моделью **`deepseek-v4.1-flash-1017`** под руководством **[EXpance](https://t.me/EXpaLab)**.

## Возможности

### Подключение
- Кнопка питания с анимацией, таймер соединения и живой статус.
- Два режима работы: **Полная работа** (VPN-тоннель со всеми настройками) и **Только прокси** (локальный SOCKS5/HTTP-прокси на `127.0.0.1`).
- Обход блокировок РФ: российские сайты идут напрямую, зарубежные — через прокси; можно пустить в прокси весь интернет и добавить свои домены.
- Автопереключение на резервный сервер при обрыве, авторотация серверов по таймеру.
- Быстрая плитка в шторке Android (запуск/остановка без открытия приложения).
- Автозапуск после перезагрузки (по желанию).

### Протоколы
| Протокол | Схема ссылки | Статус |
|---|---|---|
| SOCKS5 | `socks5://user:pass@host:port` | ✅ |
| SOCKS4 | `socks4://host:port` | ✅ |
| HTTP / HTTPS | `http://host:port`, `https://host:port` | ✅ |
| Shadowsocks | `ss://BASE64@host:port`, `ss://BASE64#name` | ✅ |
| Trojan | `trojan://pass@host:port?sni=…` | ✅ |
| VLESS (TCP + TLS) | `vless://uuid@host:port?security=tls&sni=…` | ✅ |
| VLESS (WS / gRPC / REALITY) | — | ❌ пропускаются |
| VMess / Hysteria2 / REALITY | — | ❌ не поддерживаются |

Shadowsocks поддерживает как современный AEAD (`aes-128/256-gcm`, `chacha20-ietf-poly1305`),
так и legacy-шифры, которых ещё полно в публичных списках: `aes-128/192/256-cfb`,
`aes-128/192/256-ctr` и `rc4-md5`.

Поддерживается импорт из подписки (base64-список ссылок), из буфера обмена, по глубокой ссылке `rustedproxy://add?…` и через QR-код.

### Умный сканер
- Параллельная проверка большого пула кандидатов (по умолчанию 200 воркеров) реальным HTTPS-запросом через каждый узел. Сканер сам подбирает размер пула под бюджет времени (≈45 с), чтобы каждый узел получил полный таймаут, а не обрезался на середине.
- Фильтры по протоколу, шифрованию, скорости для видео (≥ 15 Мбит/с), поддержке UDP.
- Фильтры по пингу (быстрее 100 мс, 100–300 мс, медленнее 300 мс), выбор страны, сортировка по пингу.
- Дожидается медленных узлов (гео, скорость, проверка сервисов) и хранит до 600 лучших результатов.
- Сбор бесплатных ключей из публичных подписок и V2Ray-списков; узлы с WebSocket/gRPC-транспортом, которые ядро не умеет, честно отбрасываются, а не висят в выдаче мёртвым грузом.
- Если ничего не найдено, честно пишет: «Прокси данного типа не найдено».

### Что нового в 1.0.1
- **Shadowsocks починен по-настоящему**: клиент не отправлял серверу заголовок адреса назначения (`[ATYP][ADDR][PORT]`), поэтому ни один SS-узел не мог подключиться. Теперь формат проверен на независимой реализации (SIP004: `HKDF-SHA1` + `AES-256-GCM`).
- Разбор SS-ссылок: base64 с `=` больше не отбрасывается — раньше из-за этого **весь** формат `ss://base64@host:port` считался битым.
- Trojan/VLESS: убран ошибочный запрет узлов без SNI; для публичных узлов сертификат больше не проверяется по цепочке (у них самоподписанные/чужие сертификаты), SNI из ссылки при этом отправляется как есть.
- Trojan-узлы с `type=ws` отбрасываются на этапе разбора вместо «InvalidContentType» в логе.
- Мёртвые источники заменены на живые (все 11 отдают HTTP 200), таймаут проверки по умолчанию поднят до 4 с, пул кандидатов — до 6000.
- Ошибки теперь печатаются цепочкой причин, а не голым `hop 1`.

### Безопасность и сеть
- **DNS**: DoH, DoT и UDP; серверы Cloudflare, Google, AdGuard, Quad9 или свой; отдельная кнопка проверки DNS.
- **Обход DPI**: фрагментация TLS ClientHello (split / SNI / byte), настраиваемый размер фрагмента.
- **Kill switch**: при обрыве тоннеля сеть остаётся заблокированной.
- Блокировка незашифрованных внешних соединений, отсечение QUIC и IPv6, блокировка рекламы (встроенный список), локальная сеть в обход тоннеля.
- MTU, TCP/UDP для прокси, раздельное туннелирование (белый/чёрный список приложений), два прыжка (multi-hop).
- Root-функции (только по нажатию, требуют `su`): TCP BBR и буферы ядра, kill switch на iptables, принудительный DNS для всех приложений, Always-on VPN, очистка DNS-кэша.

### Диагностика
- Проверка утечек: реальный IP против видимого, DNS, UDP.
- Speedtest через прокси: загрузка, отгрузка, пинг.
- Живой лог ядра с паузой, очисткой и копированием.
- Текущий IP, страна и город выходного узла с обновлением одним нажатием.

### Интерфейс
- Material 3, тёмная и светлая темы (системной нет — только выбор вручную), анимации перехода между вкладками.
- Адаптация под жестовую навигацию и навигацию кнопками Android.
- Онбординг при первом запуске, сохранение всех настроек между запусками.

## Установка

1. Скачайте APK из раздела [Releases](../../releases):
   - `app-arm64-v8a-release.apk` — для всех современных телефонов (рекомендуется);
   - `app-armeabi-v7a-release.apk` — для старых 32-битных ARM-устройств;
   - `app-x86_64-release.apk` — для эмуляторов и x86-устройств.
2. Разрешите установку из неизвестных источников.
3. При первом подключении Android спросит разрешение на VPN — без него тоннель не заработает.

**Требования:** Android 7.0 (API 24) и выше, `arm64-v8a` / `armeabi-v7a` / `x86_64`.

## Сборка

### Что нужно
- **Flutter 3.47+** / Dart 3.13+ (`flutter doctor` должен быть чистым)
- **Rust** stable (`rustup`) с целями Android:
  ```bash
  rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android
  ```
- **Android SDK** с `compileSdk 36`, `targetSdk 35`, `minSdk 24`
- **Android NDK** 28.x (проверено на `28.2.13676358`)
- **JDK 17**

### 1. Нативное ядро
Переменная `ANDROID_NDK` должна указывать на каталог NDK:

```bash
export ANDROID_NDK=/path/to/ndk/28.2.13676358
./tool/build_native.sh
```

Скрипт соберёт `librustedproxy_core.so` под три ABI и положит их в
`android/app/src/main/jniLibs/<abi>/`. Альтернатива — выполнить вручную:

```bash
cd rust_core
cargo build --release --target aarch64-linux-android
cargo build --release --target armv7-linux-androideabi
cargo build --release --target x86_64-linux-android
```

> Для `armv7` нужны `CC_armv7_linux_androideabi`, `CXX_armv7_linux_androideabi`
> и `CFLAGS_armv7_linux_androideabi="-march=armv7-a -mthumb"`, иначе сборщик
> `ring` падает на ассемблере.

### 2. Приложение
```bash
flutter pub get
flutter build apk --release --split-per-abi \
    --target-platform android-arm64,android-arm,android-x64
```

Результат в `build/app/outputs/flutter-apk/`:
`app-arm64-v8a-release.apk`, `app-armeabi-v7a-release.apk`, `app-x86_64-release.apk`.

Отладочная сборка: `flutter build apk --debug`.

### Подпись релиза
Скопируйте `android/key.properties.example` в `android/key.properties` и укажите
свой keystore. Файл и ключи в `.gitignore` — в репозиторий они не попадают.
Без `key.properties` сборка автоматически подписывается отладочным ключом.

### Тесты
```bash
flutter analyze          # статический анализ
flutter test             # виджеты, модели, фильтры сканера
cd rust_core && cargo test   # парсеры ссылок, маршрутизация
```

## Известные ограничения
- Публичные бесплатные списки прокси быстро устаревают: значительная часть узлов
  уже мертва (TCP-порт принимает соединение, но данные не проходят). Сканер это
  честно отсеивает; свои прокси и платные подписки работают стабильно.
- VMess, Hysteria2, REALITY и WebSocket/gRPC-транспорты не поддерживаются —
  такие узлы пропускаются на этапе разбора ссылки.
- Root-раздел появляется только при наличии `su` (Magisk / KernelSU); в debug-сборке
  переключатели видны для проверки интерфейса и систему не меняют.
- Релизные APK подписаны проектным ключом; при обновлении сохраняйте подпись,
  иначе придётся удалить старую версию.
